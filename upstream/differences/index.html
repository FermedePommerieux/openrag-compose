Differences from upstream OpenRAG

This page compares explicit repository behavior and contracts. It does not infer shortcomings from the absence of a fork-specific name, and it does not conflate the historical fork point with today's upstream project.

Method​

The comparison was produced after git fetch --all --prune from the official upstream remote. Git ancestry, trees and code at both pinned upstream revisions were inspected. Exact fork contract identifiers and entry points were searched at the fork point, current upstream and the documented fork baseline. For architecture, the corresponding search and workspace-configuration code was also read so an upstream feature under another name would not be mislabeled.

The evidence classifications used below are:

  • VERIFIED AGAINST FORK POINT — observed in the pinned common-ancestor tree;
  • VERIFIED AGAINST CURRENT UPSTREAM — observed in the separately pinned fetched upstream tree;
  • FORK-SPECIFIC CONTRACT — the behavior is defined by an explicit contract in the documented fork, without claiming that upstream lacks every adjacent capability.

What is not claimed​

This documentation does not assign fork setting names or modes to upstream OpenRAG. It claims only that the pinned upstream revisions do not contain the named fork contracts and execution paths above, and describes different upstream architecture only where the comparison is directly evidenced.

Upstream can evolve after the pinned current-upstream check. Future comparisons must fetch again, pin a new revision and keep fork-point differences separate from current-upstream differences.
