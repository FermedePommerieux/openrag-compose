1. In OpenRAG, click <Icon name="Settings2" aria-hidden="true"/> **Settings**,
   and then find the **Agent** section.

2. Change the active language model or Agent instructions in OpenRAG Settings.
   Model changes are persisted in the workspace configuration. To apply new
   instructions, click **Save Agent Instructions**. OpenRAG synchronizes these
   configured values to the managed Langflow flow.

3. To add a language model, configure its provider on the **Settings** page,
   then select the model in the **Agent** section. The planner follows the
   Agent model when its own selection is empty; API clients can configure an
   explicit planner provider/model separately.

   :::info
   OpenRAG requires at least one language model and one embedding model. If a
   previously selected provider or model is removed, chat or ingestion can
   fail until the corresponding runtime selection is changed.
   :::

4. Check `GET /api/settings/runtime-behavior` after an operational change.
   `MATCH` confirms that configured Agent/planner identities and the prompt
   hash agree with effective execution. Provider credentials are not returned.

5. For unrestricted Langflow experimentation, create and explicitly configure
   a separate custom chat flow rather than modifying the managed system flow.
   A custom flow is preserved, but it does not receive automatic migration,
   settings reapplication, prompt synchronization or the managed Retrieval v2
   guarantees. Export it before upgrades.

6. After changing supported Agent settings or selecting a custom flow, open
   <Icon name="MessageSquare" aria-hidden="true"/> **Chat** and click
   <Icon name="Plus" aria-hidden="true"/> **Start new conversation** so the
   previous conversation does not retain the earlier behavior.
